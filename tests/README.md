# تست‌های جستجو، تاریخ، ساعت و سازگاری بازیابی

## تست‌های اصلی

نیازمند PHP 8.2+ با mbstring و Node.js 18+. تست‌های SQL جستجو همچنین به افزونهٔ **pdo_sqlite** نیاز دارند (مثلاً پکیج `php8.2-sqlite3`؛ وابستگی تست است، نه اجرای سامانه):

```sh
php tests/jalali.php
php tests/time.php
php tests/search.php
php tests/birthmonth.php
php tests/followup.php
php tests/restore-check.php
DB_DATABASE=massage_test DB_USERNAME=... DB_PASSWORD=... php tests/credit.php
DB_DATABASE=massage_test DB_USERNAME=... DB_PASSWORD=... php tests/followup.php
node --test tests/*.test.js
```

اگر PHP در PATH نیست، برای تست مسیرها `PHP_BIN` را به مسیر فایل اجرایی PHP تنظیم کنید.

- `birthmonth.php`: فیلتر اختیاری ماه تولد شمسی (۱ تا ۱۲، بدون سال)، ارقام فارسی/لاتین، رد ماه نامعتبر، نادیده‌گرفتن ورودی آرایه، حذف NULL/خالی/صفر از نتایج، و recall صددرصدی روی هر روز تقویم ۱۹۲۰ تا ۲۰۲۶ در هر دو موتور SQLite و MySQL (با `BIRTHMONTH_TEST_MYSQL_DSN`).
- `birthmonth-routes.test.js`: اجرای SQL فیلتر ماه از front controller روی دادهٔ آزمایشی، ترکیب با جستجوی نام، حذف NULL/صفر/خالی از نتایج، ستون شمسی، حفظ q و ماه در صفحه‌بندی، reset و محدودبودن فیلتر به مشتریان.
- `credit.php`: منطق کیف اعتبار روی دیتابیس `*_test` جداگانه (داخل تراکنش rollbackشده): کسب درصد، idempotency، clamp مصرف، برگشت ویرایش/حذف، کف صفر، شارژ دستی و تاریخچه. روی دیتابیس اصلی اجرا نکنید.
- `followup.php`: بهبودهای مرکز پیگیری روی دیتابیس `*_test` (داخل تراکنش rollbackشده): ستون `customer_timeline.deleted_at`، ایجاد پیگیری مجدد با «X روز دیگر»، عدم ایجاد برای رزرو شد، ردیف‌های تایم‌لاین (نتیجه/زمان‌بندی) و حذف نرم تایم‌لاین.
- `followup-routes.test.js`: جستجوی نام مشتری (LIKE با پارامتر)، فیلترهای مستقل «معوق» و «امروز»، حذف گروهی نرم (soft-delete)، ثبت نتیجه با پیگیری مجدد، ردیف تایم‌لاین `followup_done` برای رزرو شد و UI انتخاب چندتایی.
- `credit-routes.test.js`: رندر فیلد مجازی `credit_used`، ثبت earn/spend در لجر از front controller، عدم ذخیره ستون مجازی، و عدم کسب برای `unpaid`.
- `search.php`: عادی‌سازی حروف/اعداد/فاصله/اعراب، نام کامل و ترتیب معکوس واژه‌ها، نام مرکب، دادهٔ قدیمی، مقدار صفر، LIKE کاملاً لفظی، ورودی نامعتبر و اجرای واقعی predicate روی ردیف‌های آزمایشی.
- `search-routes.test.js`: اجرای SQL فهرست و COUNT واقعی از front controller، نام‌های مرتبط نوبت/جلسه/پکیج، دادهٔ حذف‌شده، شمارش و صفحه‌بندی، لینک پاک‌کردن و حفاظت ورودی. برای این تست، `route-harness.php` فقط SQL فهرست/شمارش را روی SQLite حافظه‌ای با تابع سازگاری `CONCAT_WS` اجرا می‌کند؛ جست‌وجوی تولیدشده فقط از `CONCAT_WS/LOWER/REPLACE` استفاده می‌کند و به `REGEXP_REPLACE` وابسته نیست (روی MySQL قدیمی‌تر از 8.0.4 پشتیبانی نمی‌شود)؛ احراز هویت و تنظیمات همچنان آزمایشی‌اند.
- `jalali.php`: تاریخ‌های مرجع مشترک، ارقام فارسی/عربی/لاتین، جداکننده‌ها، نوروز و کبیسه، تاریخ نامعتبر/خالی، timestamp، متن قدیمی CRM، بازهٔ ماه شمسی و رندر ورودی‌ها. تبدیل رفت‌وبرگشت روزهای یازده سال نیز بررسی می‌شود.
- `restore-check.php`: پوشش جدول‌ها/ستون‌ها و تاریخ‌های فرمت قبلی، بازگشت بدون تغییرِ تاریخ ویرایش‌شده، تشخیص ستون/کلید مفقود و نوع ناسازگار، تاریخ صفر، سال مشکوک، صفحه‌بندی و جلوگیری از دستور غیر SELECT. این تست از متادیتا و ردیف‌های آزمایشی استفاده می‌کند؛ نه از فایل بکاپ واقعی یا ریستور روی MySQL.
- `time.php` و `timepicker.test.js`: الگوی مشترک ساعت، تایپ کوتاه، ارقام فارسی/عربی/لاتین، مرز نیمه‌شب، تمام دقیقه‌های شبانه‌روز، مقدار اختیاری خالی، ورودی نامعتبر، حفظ ثانیه‌های دادهٔ قدیمی و منطقهٔ زمانی میان‌بر «الان».
- `time-routes.test.js`: رندر تمام فرم‌های ساعت، ثبت/ویرایش بدون JS، ذخیرهٔ `HH:MM:SS` و `NULL`، رد ساعت نامعتبر/آرایه، حفظ ورودی پس از خطا و بررسی تداخل نوبت با ساعت نرمال‌شده.
- `jalalidatepicker.test.js`: همان تاریخ‌های مرجع در JavaScript، طول ماه، اعتبارسنجی و «امروز» در منطقه‌های زمانی متفاوت.
- `routes.test.js`: فرم‌های ویرایش و نمایش ماژول‌ها، حفظ ورودی پس از خطا، جلوگیری از ذخیرهٔ تاریخ نامعتبر، ذخیرهٔ میلادی ورودی شمسی، ایجاد پیگیری، تایم‌لاین قدیمی، مرکز پیگیری، ممیزی، لیست‌ها، نمودار، فیلتر گزارش/حقوق و CSV.

`route-harness.php` **فقط در CLI** اجرا می‌شود و تنها لایهٔ DB را با داده‌های آزمایشی جایگزین می‌کند؛ تمام تبدیل‌ها، اعتبارسنجی‌ها، سرویس‌ها و قالب‌ها از کد واقعی برنامه هستند. این تست‌ها به دیتابیس برنامه متصل نمی‌شوند و داده‌ای از آن را تغییر نمی‌دهند. اجرای SQL جستجو روی SQLite از پاسخ ساختگیِ همیشگی برای LIKE جلوگیری می‌کند، اما جایگزین بررسی سازگاری روی MySQL/MariaDB نیست.

برای بررسی عملیِ دیتابیس بازیابی‌شده، دستور `backup:check` و محدودیت‌های آن در [راهنمای بازیابی](../docs/RESTORE.md) توضیح داده شده‌اند.

## تست اختیاری مرورگر

برای تست تعامل واقعی تقویم و ساعت، Playwright و Chromium لازم است (وابستگی توسعه، نه اجرای سامانه):

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node tests/datepicker.browser.cjs
node tests/timepicker.browser.cjs
node tests/search.browser.cjs
node tests/birthmonth.browser.cjs
```

برای استفاده از Chromium موجود، `CHROMIUM_PATH` را تنظیم کنید. این تست ورود دستی، رد تاریخ نامعتبر، انتخاب روز، جابه‌جایی نوروز/اسفند کبیسه، پاک‌سازی، بازنشانی فرم، محدودیت بازه، تبدیل ورودی native و پویا، فیلد readonly/disabled و اختلاف ساعت تهران/مرورگر را بررسی می‌کند.

`timepicker.browser.cjs` ورودی‌ها را با `View::timeInput` واقعی PHP می‌سازد و بدون CDN تست می‌کند: تایپ و خطا، انتخاب/لغو/پاک‌کردن، کیبورد و رویدادها، فرم اختیاری/الزامی، ثانیه‌های قدیمی، reset، ورودی پویا، readonly/disabled، هم‌زیستی با تقویم شمسی، منطقهٔ زمانی، موبایل و تم تیره. در صورت نیاز `PHP_BIN` را تنظیم کنید. برای تصویر QA، متغیر اختیاری `BROWSER_ARTIFACT_DIR` را به پوشه‌ای خارج از Git اختصاص دهید.

`search.browser.cjs` با JavaScript خاموش، فرم GET واقعی و SQL داده‌های آزمایشی را بررسی می‌کند: ورود با Enter و دکمه، حفظ املای عبارت، بازگشت جستجوی جدید به صفحهٔ اول، حفظ عبارت بین صفحه‌ها، پاک‌کردن، نتیجهٔ خالی و جستجوی نام مشتری در نوبت‌ها. نیازمند PHP با pdo_sqlite است.

`birthmonth.browser.cjs` همان فرم واقعی مشتریان را با JavaScript روشن و خاموش تست می‌کند: انتخاب ماه از select، ترکیب با جستجو، نمایش تاریخ تولد، صفحه‌بندی، پاک‌کردن، نتیجهٔ خالی و چیدمان موبایل/تم تیره. `browser-app.cjs` فقط ابزار مشترک مرورگر برای HTML و دادهٔ ساختگی است؛ سرور یا دادهٔ Production نیست. خروجی تصویر اختیاری در `BROWSER_ARTIFACT_DIR` خارج از Git ذخیره می‌شود.

برای بررسی تصویری با CSS واقعی Bootstrap و بدون شبکه، می‌توانید `BOOTSTRAP_CSS_PATH` را به فایل محلی `bootstrap.rtl.min.css` نسخهٔ ۵.۳.۳ تنظیم کنید؛ در تست مرورگر به‌جای درخواست CDN همان فایل خوانده می‌شود. این فایلِ اختیاری را خارج از Git نگه دارید.

## تست اختیاری روی موتور MySQL/MariaDB

برای اجرای همان predicateها با موتور واقعی، **فقط اتصال یک دیتابیس تست جداگانه** را در `SEARCH_TEST_MYSQL_DSN` (مانند `mysql:host=127.0.0.1;dbname=massage_search_test;charset=utf8mb4`)، `SEARCH_TEST_MYSQL_USER` و `SEARCH_TEST_MYSQL_PASSWORD` از طریق محیط تنظیم و `php tests/search.php` را اجرا کنید. رمز را در مخزن یا خط فرمان مشترک ذخیره نکنید. هیچ fallback به اتصال `.env` برنامه وجود ندارد.

در این حالت داده‌ها در جدول‌های **TEMPORARY** با collation حساس `utf8mb4_bin` ساخته می‌شوند و با پایان اتصال حذف می‌شوند؛ جدول‌های دائمی تغییر نمی‌کنند. حساب تست به مجوز ساخت جدول موقت نیاز دارد. MySQL 8+ یا MariaDB 10.6+، همان نسخه‌های مورد نیاز برنامه، لازم است. حالت `NO_BACKSLASH_ESCAPES` نیز بررسی می‌شود. اجرای پیش‌فرض SQLite نباید به‌عنوان تست موفق MySQL یا ریستور بکاپ گزارش شود.
